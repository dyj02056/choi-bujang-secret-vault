# BYTE BACK 방어전 - 점령된 자료실 (3단계)

이 저장소는 3단계 자료실 보호 기능이 적용된 상태입니다. Supabase Auth 및 서버 토큰 검증을 통해 로그인한 사용자만 가상 메모를 조회·추가·수정·삭제할 수 있습니다.

## 3단계 현재 작동하는 기능

1. **Supabase Auth 사용자 인증:**
   - 화면에서 이메일·비밀번호로 회원가입 및 로그인, 로그아웃이 가능합니다.
   - 로그인하지 않은 상태에서는 메모가 노출되지 않으며, 로그인 후에만 메모 목록 및 관리 UI가 활성화됩니다.
2. **서버 API 토큰 검증 (`src/verify-login.mjs` 연동):**
   - `/api/notes` (목록 조회 GET, 생성 POST)
   - `/api/notes/:id` (단건 조회 GET, 수정 PUT, 삭제 DELETE)
   - 무인가/비로그인 요청 시 401 오류와 JSON 메시지를 반환합니다.
3. **가상 메모 CRUD:**
   - 로그인한 사용자가 본인 계정으로 새 메모를 작성하면 `owner_id`가 서버에 의해 자동 기록됩니다.
   - 메모 단건 조회 및 수정, 삭제가 가능하며 삭제 후 조회 시 404를 반환합니다.

## 알려진 보안 허점 (4단계 보완 예정)

- 현재 서버 API는 로그인 여부만 검사하고, 개별 메모의 소유자(owner_id) 일치 여부는 검증하지 않습니다. 따라서 로그인된 다른 사용자 B가 사용자 A의 메모 ID를 알면 메모를 수정하거나 삭제할 수 있는 허점이 남아 있습니다. (4단계에서 소유자 검증 기능 추가 예정)

## 다시 실행 및 테스트 방법

1. **로컬 빌드 검증:**
   ```powershell
   npm run build -- --local
   ```
2. **환경변수 설정 (Vercel 및 배포 환경):**
   - `SUPABASE_URL`: Supabase 프로젝트 URL
   - `SUPABASE_SECRET_KEY`: Supabase `service_role` 키
3. **배포 및 동작 확인:**
   - 배포된 URL 접속 후 로그인/로그아웃 상태에 따른 화면 변화 확인
   - 가상 메모 추가, 수정, 삭제 동작 확인
   - 비로그인 상태에서 `GET /api/notes` 호출 시 401 JSON 응답 반환 확인
