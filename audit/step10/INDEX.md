# 10단계 기록 모음

10단계(백업에서 자료실을 되살립니다)에서 실제로 일어난 일의 기록입니다. 아래 파일들은 모두 추가만 합니다.
줄을 지우거나 고치거나 덮어쓰지 않습니다. 새 내보내기는 새 이름의 파일로 만들어집니다 (`npm run audit:export`).

## 파일

| 파일 | 내용 | 만든 방법 |
|---|---|---|
| `db-audit-trail.jsonl` | DB 감사 기록의 모든 줄. 한 줄에 사건 하나이며, 새로 생긴 줄만 뒤에 이어 씀 (고정 이름) | `npm run audit:export` |
| `db-backups.jsonl` | DB 메모 사본의 정보(메모 ID, 가명 소유자, 내용 해시, 시각). 제목·내용 없음. 새 줄만 이어 씀 (고정 이름) | `npm run audit:export` |
| `export-<UTC 시각>.json` | DB 감사 기록 전체 줄(`db.auditTrail`), 메모 사본의 정보(`db.backups`), 10단계 저장점 커밋(`git`), 그 시점의 직접 점검 15개 결과(`attackResults`) | `npm run audit:export`가 DB와 깃과 `artifacts/submission.json`을 읽어서 만든 것 |
| `deployments.json` | 10단계 저장점 6건의 Vercel 배포 이력(배포 ID, 시각, 커밋, 상태) | Vercel `list_deployments` 응답에서 옮겨 적은 것 |
| `../restore-audit.log` | 로컬 절차(정책 사본 검증·복원 시험, 메모 사본 생성·검증, 내보내기)의 한 줄 기록 | 각 스크립트가 실행될 때 추가 |

## 담지 않은 것
- 메모 제목과 내용, 토큰, 서버 키는 읽지도 저장하지도 않았습니다. 내용은 SHA-256 해시로만 남아 있습니다.
- 계정 ID 원문은 넣지 않았습니다. `owner_xxxxxxxxxx`는 계정 ID를 해시한 앞 10자리이며 원래 ID로 되돌릴 수 없습니다. 같은 값은 같은 계정입니다.
- 반 엔진의 기록은 운영 측이 가지고 있어서 이 저장소에 없습니다.

## 확인되지 않은 것
- #4(04:56)와 그 밖의 호출이 어느 명령에서 나왔는지는 기록에 없습니다.
- 직접 점검 결과(`attackResults`)는 내보낸 시점에 남아 있던 가장 최근 실행 하나뿐입니다. 이전 실행의 결과 파일은 덮어써져서 남아 있지 않습니다.
- 이 기록이 심판이 말하는 감사 기록인지는 확인하지 못했습니다.
- 마이그레이션 `007`(거절 기록, TRUNCATE 금지)을 실서버 DB에 실행했는지와, 그 뒤의 `refused` 기록은 아직 이 디렉토리에 없습니다. 실행 뒤 `npm run audit:export`로 새 줄을 이어 씁니다.
